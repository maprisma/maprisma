2. **`flutter_app/lib/overlay_window.dart:11, 19-28` — Resizing `OverlayWindow` throws `ArgumentError` when the app body is smaller than `420 × 300`, and dragging a single edge overwrites the orthogonal dimension in `_chosen`**
   - **What goes wrong:**
     - In `OverlayWindow.build` (`flutter_app/lib/overlay_window.dart:68-71`), `shown` safely clamps to `(0, room.width)` and `(0, room.height)` when the available body `room` is smaller than `OverlayWindow._minimum` (`420 × 300`). However, in `_drag` (`flutter_app/lib/overlay_window.dart:19-27`):
       ```dart
       final wide = (shown.width + 2 * delta.dx * x).clamp(
         OverlayWindow._minimum.width,
         area.width,
       );
       final high = (shown.height + 2 * delta.dy * y).clamp(
         OverlayWindow._minimum.height,
         area.height,
       );
       ```
       `double.clamp(lowerLimit, upperLimit)` throws `ArgumentError` whenever `lowerLimit > upperLimit`. If the app window is resized so the body area is narrower than `420` px or shorter than `300` px and the user drags any edge or corner of `OverlayWindow`, `_drag` throws an unhandled `ArgumentError`.
     - In addition, `_drag` always writes both `wide` and `high` into `OverlayWindow._chosen = Size(wide, high)` even when `x == 0` (dragging top or bottom edge only) or `y == 0` (dragging left or right edge only). When `_chosen` is initially `null` (using the default `80% × 85%` proportional size), dragging only the top/bottom edge also freezes the current pixel width into `_chosen`; and if the app window was temporarily narrowed below `_chosen!.width` so `shown.width < _chosen!.width`, dragging the top or bottom edge permanently overwrites `_chosen!.width` with the clamped `shown.width`.
   - **How to reproduce:** Shrink the app window so its body height is under `300` px (or width under `420` px), open `Help` (or any `OverlayWindow`), and drag any edge of the overlay window: `clamp(300.0, area.height)` throws `ArgumentError`. Or, with default `OverlayWindow._chosen == null`, drag only the bottom edge to change height and then widen the app window: the overlay width no longer scales at 80% because `_chosen` recorded a fixed pixel width.

2. Fixed. Width and height are chosen separately, so one edge leaves the other following the app, and the minimum gives way when the app is smaller. Test: 'the window drags its size'.

6. Fixed. `_keysBlocked` holds while any window or terminal is open; the header buttons and the app's keys use it, zoom too. Buttons inside a window still work. This reverses "the header's buttons still work" from 013.
7. Fixed by a small step: applying the slot Preview removes the older message. That change's Undo stays in Connections and Recent changes.
8. Fixed. Starting another drawing ends the click, the dragged line's own hook stays; only movable lines are stored, and the key has the kind. A new graph keeps the click on purpose: live updates would hide the hook.
9. Fixed: both paragraphs rewritten in 8 languages, formal as the chapter is, UI names as the app shows them. Also corrected Übernehmen in German and Desfazer in Portuguese.
