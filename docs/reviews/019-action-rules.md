1. **`packages/maprisma_core/lib/src/action_rules.dart:204-211` — Removing an agent (`agents.action_preview`) is checked as `connect` instead of `remove`, and `verify` is checked as `connect` instead of `start`**
   - **What goes wrong:** `actionChecks` for `'agents.action_preview'` maps `const {'install', 'update', 'remove'}.contains(action) ? action : action == 'logout' ? 'disconnect' : 'connect'`. However, `agents.action_preview` never takes `action: 'remove'`: `AgentActions.resolve` (`packages/maprisma_core/lib/src/agent_actions.dart:368`), `AgentDetailsView` (`flutter_app/lib/agent_details_view.dart:99`), and `smartAgents` (`packages/maprisma_core/lib/src/smart_card.dart:290`) all pass `action: 'uninstall'`. Because `'uninstall'` is not in `{'install', 'update', 'remove'}`, it falls through to `'connect'`, producing `ActionCheck('connect', 'agents', command)`. Likewise, `action: 'verify'` ("Send the test question", which starts the agent in a terminal via `starter.start` in `packages/maprisma_core/lib/src/core.dart:1233`) falls through to `'connect'` instead of `'start'`.
   - **How to reproduce:** In **Settings › What may be done**, add `Deny: Remove, Agents, All` (or `Deny: Remove, All, All`). Open an installed agent's details and click **Remove** (or ask Ask AI in the Agents column to remove it): the preview opens and uninstalls the agent instead of being refused. Conversely, adding `Deny: Connect, Agents, All` blocks uninstalling an agent and sending the test question.

### Answers (Claude)
1. Fixed: `uninstall` is remove, `verify` is start. The table was written from guessed names; it is now written from the handlers.
2. Fixed. Checks stay with every handle under the keys plan, preview, token, task and installer, without the prefix. `tasks.status` carries them from a worker's task to its token. `_disconnectAll`, `checks.mcp_task` and `agent_task` keep theirs.
3. Fixed. "Do it with …" and MCP update tasks are start, Security settings and slots are update. A refused slot step stays silent, as it asks nothing of the user.
4. Fixed. Downloads use the repo, imports the path. Models compare without case, skill folders in the `~/` form, in one `_ruleItem`. `found.update_preview` reads `program`, and without one checks each server. A new MCP server by form also checks install. `models.switch_preview` checks the agents on the line.
5. Fixed: `installers.preview` is update for what is installed, `updates.run` takes its category from the update entry.
6. Fixed. `_taskResult` and the Connections paths use `failureText`, and a refusal counts for three seconds only, so it cannot explain a later failure.
7. Fixed. `narrower` looks at the action. `_dropRefused` takes refused candidates off the card before Review, and with none left the card says it is not allowed. The helper gets only its column's rules, with no skill path. Skill folders reach it as short ids: 018 had sent paths, which this also ends. A lookup cannot be refused beforehand, since its question is free text; the prompt forbids it when hints are off.
8. Fixed: the bar shows the deciding rule, and has no agent where none applies.
9. Fixed: Undo after Restore defaults, no map scan on a rule edit, the rules button does nothing while something runs, the refusal names translated action and category, with the agent. The `print` was gone already.

`action_rules_test` now holds real parameters and the expected action, category and item per route.
