## Round 1 (Antigravity, 2026-11-03, commit af0868e)

1. **High** `tools/flutter-assets.py:7` The two new lock texts (`"{0} is running in a terminal. Add-ons can be changed when it has finished."` and `"{0} are running in terminals. Add-ons can be changed when they have finished."`) and `"Show terminal"` (used at `flutter_app/lib/map_addons_focus.dart:10,60` and `flutter_app/lib/main.dart:1076,1249`) were added to `translations/*.json`, but were not added to `KEYS` in `tools/flutter-assets.py` or exported into `flutter_app/assets/translations/{de,es,fr,it,nl,pl,pt}.json`. Because `_MaprismaAppState._loadLanguageStrings` (`flutter_app/lib/main.dart:4088`) loads UI translations from `assets/translations/$language.json`, `tr(...)` falls back to the raw English keys in all 7 non-English languages whenever the lock banner, tooltips, menu subtitle, details sheet, or snack bar are displayed.
   - **How to reproduce:** Set the app language to `de` (or any non-English language), start an agent in an embedded terminal, and open the `Add-ons` focus view or trigger a blocked add-on action. The lock banner, `Show terminal` button, tooltips, and snack bar are shown in English instead of the translations in `translations/de.json`.
   > Author: Fixed in 5073b1a: the two lock texts and `Show terminal` are in `KEYS` of `tools/flutter-assets.py`, and the 8 asset files are regenerated. New map_groups_test "every text of the add-ons page is in the app's translations" checks every `tr('…')` of `map_addons_focus.dart` against all 7 asset files (fails on af0868e).

2. **High** `flutter_app/lib/main.dart:1247` Clicking `Show terminal` in the add-on details sheet (`_addonMenu`) closes the sheet but never shows the running terminal. `_addonMenu` (`flutter_app/lib/main.dart:1224`) opens `showModalBottomSheet` inside `_review(...)` (`flutter_app/lib/main.dart:1014-1021`), which increments `_reviewDepth` to `1` and only decrements it in its `finally` block after the sheet's route future completes asynchronously. Inside the `Show terminal` button's `onPressed`, `Navigator.pop(sheet)` is followed synchronously by `_showRunningTerminal()` (`flutter_app/lib/main.dart:1248-1249`) while `_reviewDepth` is still `1`. `_showTerminal` (`flutter_app/lib/main.dart:1045`) checks `if (_navigationBlocked || _card != null) return;`, and `_navigationBlocked` (`flutter_app/lib/main.dart:333`) is `true` while `_reviewDepth > 0`, so `_showTerminal` returns early without setting `_visibleTerminal`.
   - **How to reproduce:** Start an agent in an embedded terminal, return to the map, open `Add-ons`, click an add-on card to open its details sheet, and click `Show terminal` (`Key('addon-sheet-show-terminal')`). The bottom sheet closes, but the app stays on the map instead of switching to the running terminal.
   > Author: Fixed in 5073b1a: the sheet's Show terminal (`addon-sheet-show-terminal`) only pops the sheet with `'terminal'`; `_showRunningTerminal()` runs after `_review` has returned, when `_reviewDepth` is 0 again. Covered by task_cards_app_test "while an agent runs, add-on changes say why and the lock lifts when it ends" (the terminal is visible after the tap; fails on af0868e).

3. **Medium** `flutter_app/lib/main.dart:2828` Single add-on updates (`Update add-on to {0}`) and add-on installs (`Get add-on`, `Install from file…`) are not guarded against running agents. While `_updateAllAddons` (`flutter_app/lib/main.dart:1780`) checks `if (_agentsRunning) return _addonsLocked();`, individual card updates (`flutter_app/lib/map_addons_focus.dart:204`, `flutter_app/lib/main.dart:1277`) and `Get add-on` (`flutter_app/lib/map_addons_focus.dart:444`) call `_installAddon(entry)` (`flutter_app/lib/main.dart:2828`), which only checks `if (_busy) return;` (and `_installAddonFile` at `flutter_app/lib/main.dart:2778` and the `Install from file…` button at `flutter_app/lib/map_addons_focus.dart:421` likewise only check `_busy` / `widget.busy`). If a user clicks `Update add-on to {0}` from an already-open card popup menu after an agent starts, races a click on `Update add-on to {0}` / `Get add-on`, or clicks `Install from file…` while an agent terminal is running, the app opens `AddonInstallReview` and runs `addons.install` instead of refusing with `_addonsLocked()`.
   - **How to reproduce:** Start an agent in an embedded terminal, open `Add-ons`, and click `Install from file…` (or open an add-on card's `⋯` menu before the terminal starts and click `Update add-on to {0}` once it is running). The install/update flow proceeds instead of showing `addons-locked-snackbar`.
   > Author: Fixed in 5073b1a: `_installAddon` and `_installAddonFile` return `_addonsLocked()` while agents run (same snack bar as the other actions), and Install from file… (`addons-install-file`) is disabled with the reason as tooltip. Covered by task_cards_app_test "while an agent runs, add-on changes say why and the lock lifts when it ends" (Get add-on, a single update and Install from file).

4. **Medium** `flutter_app/lib/main.dart:1223` The add-on details sheet (`_addonMenu`) computes `final blocked = _busy || _agentsRunning;` once before opening `showModalBottomSheet`, and the modal sheet's builder does not rebuild when `_track` calls `setState(() {})` on `_MaprismaAppState` (`flutter_app/lib/main.dart:1056`). If the last running agent terminal finishes while the details sheet is open, the `addon-sheet-locked` banner remains visible and `Switch on`/`Switch off`, `Update add-on to {0}`, and `Remove` stay disabled until the sheet is closed and reopened.
   - **How to reproduce:** Start an agent in an embedded terminal, open an add-on card's details sheet in `Add-ons` so the lock banner and disabled buttons are shown, and let the terminal finish (`session_ended`). The sheet stays locked until dismissed and reopened.
   > Author: Fixed in 5073b1a: the sheet is built in a `ListenableBuilder` on `Listenable.merge(_terminals)` and computes `blocked` and its text on each build, so it unlocks when the last agent ends. Covered by task_cards_app_test "while an agent runs, add-on changes say why and the lock lifts when it ends" (an open sheet unlocks after `session_ended`).
