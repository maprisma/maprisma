## Round 2 (Antigravity, 2026-11-01, commit c516318)

1. **`FoundOnPcView` lists already-configured model folders and already-connected local LLMs as newly found items** (`flutter_app/lib/found_on_pc_view.dart:29-32`, `82-85`; `packages/maprisma_core/lib/src/system_map.dart:1157-1177`, `1493-1506`; `flutter_system_map.py:553-563`, `725-737`).
   - In `system.refresh`, discovered records whose path is not yet configured become `found:*` nodes with `status: 'found'` (`system_map.dart:1167-1170`), whereas records whose path already matches a configured `folder:<path>` (`status: 'present'`) or `runtime:<key>` (`status: 'running'` / `'stopped'`) do not get a `found:*` node (`system_map.dart:1160-1166`).
   - However, `publicSystemMap` (`system_map.dart:1493-1506`, `flutter_system_map.py:725-737`) attaches `n['found'] = hit['found']` and rewrites `n['kind']` from `'folder'` to `'models'`/`'store'` on *every* node in `visible['nodes']` whose path matches a scan record, including already-configured `folder:` and `runtime:` nodes (so a newly found runtime can pick an existing folder in `_runtime`'s dropdown).
   - Because `FoundOnPcView.build` (`found_on_pc_view.dart:82-85`) filters top-level cards by `_found` (`n['found'] != null && n['status'] != 'missing'`, `lines 29-32`) instead of `n['status'] == 'found'`, any already-configured model folder or reconnected local LLM on a non-hidden disk path continues to appear in **What we found** even after it is connected. Clicking **Reuse model folder** on such a folder opens a preview with *"No changes to apply"* (`Apply` disabled); clicking **Reconnect** on an already-connected runtime fails with *"The action could not be completed."* because the wrapper/unit files under `HOME` already exist (`packages/maprisma_core/lib/src/existing_ai.dart:624-627`).
   - **How to reproduce:** Have a non-hidden GGUF folder on a local disk already in `model_folders` (or run **Find existing AI** › **Reuse model folder** › **Apply** on a found GGUF folder once), then click **Find existing AI** again. **What we found** still lists that `folder:...` node instead of *"Nothing new found."*; clicking **Reuse model folder** shows *"No changes to apply"*.

2. **Cancelling the `Preview` dialog in `_reconnect` closes *What we found* and discards the view** (`flutter_app/lib/main.dart:2452-2482` at `dd3c65b`; `2423-2453` at `c516318`).
   - In `_openFound` (`main.dart:2460-2463`), `onReconnect` immediately calls `_cancelReview?.call()` (closing the **What we found** task card) before `_reconnect` calls `_client.existingPreview(...)` and `confirmExisting(...)` (`main.dart:2475-2481`). If the user clicks **Cancel** in the **Preview** dialog (`!await confirmExisting(...)`), `_reconnect` returns at line 2481 and **What we found** is already gone.
   - **How to reproduce:** Run **Find existing AI** when a model folder or local LLM is found, click **Reuse model folder** (or **Reconnect**), and click **Cancel** in the **Preview** dialog. Both the dialog and **What we found** close; inspecting the found items again requires re-running **Find existing AI** (a full disk scan).

2. Fixed: `_reconnect` closes What we found only after the preview is applied, and a second click while a preview loads does nothing. App test: Cancel keeps the view, Apply closes it.
