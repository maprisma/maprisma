# Maprisma protocol

The contract between the GUI (`flutter_app`) and the core (`packages/maprisma_core`). Generated by
`tools/protocol.py doc` from `packages/maprisma_core/protocol/routes.json`; edit that file, not this one.

Protocol version **2**. A request is `{"id", "protocol", "method", "params"}`, the answer
`{"id", "result"}` or `{"id", "error": {"code"}}`. Kinds: **read** changes nothing; **preview** returns a plan
and changes nothing; **change** changes files or state (after a preview where there is one); **handle**
takes the handle a preview or start returned (`plan`, `undo`, `task`, `session`).

`?` marks a parameter type or a result shape not described yet: describe it when you touch the route.
A parameter written `name?` may be left out.

## features

| Route | Kind | Params | Result |
|---|---|---|---|
| `features.call` | change | `operation`: string, `params`: object, `plugin`: string, `refresh?`: bool | {} Call an operation owned by a feature plugin. AI Project Center supports profiles (profiles and detected runtimes with agent provider/model bindings), setup {id,revision,request,agent?,target?} (asynchronous no-tools team proposal; target plan or run, default run), and setup_apply {id,revision} (reviewed proposal to its saved team, no execution), alongside project lifecycle operations. Save accepts team for execution and optional plan_team for planning; absent or null plan_team uses team (saving null clears a planning override). Save also accepts setup_requests {plan?,run?} to retain prompt drafts without launching a helper. Each team can select different agents, provider/runtime/model, roles and permissions. Approval binds both setups and the launch-affecting profile facts (argv, options, permissions, runtime provider binding), not refreshing model catalogs. Project views (get and every mutation result) add derived approval_valid and processes_stopping (a supervisor of an earlier controller still owns processes of this project; the project and its folder stay busy). Generating a setup proposal leaves the project state and approval unchanged; a failed, stopped or interrupted setup records setup_error instead. setup_apply refuses a paused, interrupted or failed execution checkpoint. Pause remains available after a storage fault, which stops all active work. Model selections are session-only. Setup uses detected choices and explains recommendations; unavailable requirements fail without silently substituting agents. Plugins validate their operation and permissions; this route grants no arbitrary core method access. Optional refresh: true (consumed by the host, never forwarded) grows the host's discovery generation so the feature rebuilds its cached profile and runtime snapshot. Result {project, message {id, at, mode, text, state, run_id}, continued (now: the new session started), reason (null, or the error code that kept a now message from continuing; the project then stays paused or as the pause left it and the message stays queued)}. Waiting messages go, oldest first, into the prompt of the next assignment dispatched by any launch (plan, run, continue; not team setup), each exactly once: delivered only when that assignment's process started, then recorded in the handoff; a launch that never started keeps them queued, and messages left waiting when a run ends go to the next launch. A prompt passed as one argv word over 120 KiB is refused before launch (project_prompt_too_large; the bounds keep it near 100 KiB). Project views carry messages [{id, at, mode, text, state queued|delivered, run_id, delivered_at?, delivered_to? {phase, position, agent, role}}] (the last 20; waiting ones are never dropped) and messages_queued; list cards carry messages_queued. message_drop {id, message_id} removes a waiting message in any status (also after its run ended): project_message_unknown, project_message_delivered, project_message_invalid, project_store_full (only this request); result {project}. Events: message (sent), message_dropped, message_delivered, message_waiting (a now message could not continue, or one is left when the run ended). |
